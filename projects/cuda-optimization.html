Abstract

This work optimizes CUDA implementations for fixed deep-learning workloads on NVIDIA’s sm_120 architecture. Success is conjunctive: every variant must be numerically correct, memory-safe, and at least 1.2× faster than the PyTorch reference. The workflow combines differential localization, per-kernel profiling, one-turn optimization experiments, automatic rollback of regressions, and complete provenance. Two task tracks were completed under this process; one active cross-attention backward task spans 16 workload variants.

1. Optimization contract

A fast median is insufficient. Each workload independently gates promotion:

  • the CUDA extension compiles for sm_120;
  • all output and gradient tensors pass the numerical checker;
  • Compute Sanitizer reports no memory errors;
  • CUDA is at least 1.2× faster than the framework reference on every target shape;
  • the final artifact includes source, benchmark JSON, report, and an auditable iteration record.

This contract changes the search. A technique that wins on 15 shapes and regresses one cannot ship. A kernel that appears fast because it silently computes the wrong gradient is recorded as a failed experiment.

2. Profile, change, replay

Each iteration records the exact source difference, profiler observation, sanitizer result, next hypothesis, and whether the attempt failed. When iteration two or later regresses, the code is rolled back but the negative result remains in the trajectory. This keeps the optimization path reproducible and prevents the same idea from being retried without new evidence.

3. Localizing correctness before tuning speed

Backward kernels can produce many apparently related failures from one early error. The useful question is not “which final weights are wrong?” but “what is the first intermediate tensor that diverges?” For the cross-attention workload, attention probabilities, context gradients, value gradients, and output projections were clean in one diagnostic lineage; corruption first appeared in attention-score gradients and propagated into query/key paths and downstream weights.

That boundary sharply narrows the search to masking, scale, layout, reduction, and transpose logic around grad_attention_scores. Compute Sanitizer then distinguishes numerical mistakes from out-of-bounds access or races. Correctness checks run across all shapes because a launch geometry valid for the common n_text=77 case may fail elsewhere.

4. Blackwell-specific performance work

Nsight Compute is used to determine whether a candidate is limited by tensor cores, memory traffic, occupancy, launch overhead, or dependency chains. Common interventions include:

  • fusing adjacent pointwise operations into producer or consumer epilogues;
  • tiling reductions to keep reused values in registers or shared memory;
  • specializing common sequence dimensions while retaining a correct general path;
  • reducing global-memory round trips for transposes and gradient accumulation;
  • using library GEMMs through compliant dynamic loading where hand-written matmul is not competitive;
  • batching small work to amortize launches without increasing synchronization cost.

Performance is always measured end to end. A microkernel can look excellent while integration adds layout conversions or temporary buffers that erase the gain.

6. Lessons

  1. Localize the first incorrect intermediate before touching performance.
  2. Read profiler evidence as a causal claim to test, not a list of utilization percentages.
  3. Keep the common shape fast without violating uncommon-shape correctness.
  4. Rollback code, retain evidence.
  5. Ship only after the full workload matrix passes; spot checks create misleading confidence.
Central finding. Kernel optimization becomes much more reliable when every change is treated like a falsifiable experiment with a saved artifact, a specific bottleneck claim, and an all-shape replay.
